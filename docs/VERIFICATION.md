2026년 10월 14일 실행한 테스트의 기준과 결과다. 작은 입력에서 먼저 정한 기대값과 실제 DB 및 보고서를 비교하고, 실제 수집 프로세스를 종료한 후 재실행했다.

최초 실패에는 앱 모듈이 없는 상태의 오류가 포함돼 있다. 테스트의 개수와 subTest 실패 개수는 다른 값이다. 기대 결과 자체는 애플리케이션 코드로 생성하지 않았다.

## 실행 환경

Linux는 WSL2 Ubuntu-22.04, Python 3.10.12, SQLite 3.37.2다. Windows 디렉터리가 WSL에 마운트되지 않은 환경이라 코드·테스트·입력 파일의 복사본을 Linux 임시 디렉터리에 전달해 실행했다. 최종 Linux 로그에 각 전달 파일의 SHA-256과 전체 소스 목록의 식별값이 기록돼 있다.

Windows는 Windows 11, Python 3.13.4, SQLite 3.49.1이다. Windows에서는 SIGKILL 실험을 통과로 표시하지 않고 POSIX 전용 테스트를 제외했다.

## 강제 종료 실험

배치 크기는 4, 종료 대상은 두 번째 배치다. 첫 번째 배치는 입력 1~4줄, 두 번째 배치는 5~8줄이다. 테스트 전용 훅이 해당 지점에 도착했다는 신호를 부모에게 전달하면 부모가 SIGKILL로 수집 프로세스를 종료한다. 종료 상태는 -9이며 정상 완료 요약을 출력하지 않는지도 검사한다.

| 종료 지점 | 종료 직후 커밋된 이벤트 | 종료 직후 오류 기록 | 재실행 후 이벤트와 오류 | 반복 결과 |
| --- | --- | --- | --- | --- |
| 커밋 직전 | 4 | 0 | 5, 5 | 3회 모두 정상 실행과 동일 |
| 커밋 직후 | 5 | 1 | 5, 5 | 3회 모두 정상 실행과 동일 |

모든 복구 실험에서 PRAGMA integrity_check는 ok였다. journal_mode는 delete, synchronous는 2였다. 최종 Linux 로그의 CRASH_EVIDENCE 행에 각 반복의 종료 지점, 상태, 건수와 입력 식별값이 있다.

동일 결과 비교만으로는 정상 실행도 틀렸을 가능성을 배제할 수 없으므로 복구 결과와 정상 실행을 비교한 뒤 둘 모두 수작업으로 정한 [기대 보고서](../fixtures/expected-report.json)와 비교한다.

## 검증 범위

고정된 파일을 같은 순서로 재처리하는 단일 수집 프로세스에서 검증했다. 커밋 전과 후의 프로세스 강제 종료를 검사했으며 커밋 내부의 임의 지점, OS 전원 차단, 디스크 오류, 다중 수집자 및 분산 트랜잭션을 시험한 것으로 확대하지 않는다. 성능 수치는 아직 측정하지 않았다.

## 재현

Linux에서 저장소 루트의 python3 -m unittest discover -s tests -v를 실행하면 강제 종료 실험을 포함한다. Windows에서 python -m unittest discover -s tests -v를 실행하면 일반 테스트를 수행하고 POSIX 테스트는 제외한다. Windows에서 Ubuntu-22.04 WSL을 사용하면 python tools/run_linux_tests.py --stage final로 Linux 복사본 실행과 기록 저장을 재현할 수 있다.
